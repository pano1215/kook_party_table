# 모꾸 (모임 꾸미기)

> A little party, a lot of love.
> 좋아하는 사람들과 집에서 좀 더 특별하게. 손님 취향을 먼저 모아, 모두가 먹을 수 있는 메뉴로 홈파티를 준비하는 서비스.

KAIST APP 창업 프로그램 프로젝트. 예전 이름은 '쿸(kook)'이며 2026-11-22에 '모꾸'로 바꿨다.

## 어떻게 쓰나
1. 호스트가 모임 종류를 고르고 파티를 만든다. 초대 링크가 복사되고 보내기 창이 뜬다.
2. 게스트는 링크를 열어 앱 설치·가입 없이 취향 카드(먹고 싶은 것, 못 먹는 것, 맵기, 음료)를 보낸다.
3. 호스트는 '테이블 꾸미기'에서 손님 취향에 맞춘 메뉴 조합을 추천받는다. 알레르기·비추 재료가 든 메뉴는 자동으로 빠진다.
4. '장보기·배달'에서 재료 목록을 보고, 밀키트·배달 메뉴는 쇼핑·배달 앱으로 이어 간다.

## 여러 사람이 접속하는 방식
- 이 저장소를 Vercel에 연결해 배포하면 **배포 주소 하나로 누구나 접속**한다. 호스트와 게스트가 서로 다른 휴대폰·PC에서 같은 파티를 본다.
- 파티·취향 카드는 서버 저장소(Supabase 또는 Upstash Redis)에 저장된다. 둘 중 하나가 Vercel 프로젝트에 연결되어 있어야 한다(`/api/config`의 `"storage":true`, `"storage_kind"`로 종류 확인).
- `index.html`을 파일로 직접 열면 그 브라우저에만 저장되는 미리보기로 동작한다. 실제 서비스는 배포 주소로 쓴다.

## 인스타그램 릴스·피드·스토리 유입 분리 (2026-11-24)

- 공식 웹 주소: https://mokku-party.vercel.app
- **릴스:** https://mokku-party.vercel.app/?src=instagram_reels
- **게시물(피드):** https://mokku-party.vercel.app/?src=instagram_feed
- **스토리:** https://mokku-party.vercel.app/?src=instagram_stories
- 기존 `?src=instagram` 유입은 **인스타그램 · 미구분**으로 집계하여 이전 기록과 링크 호환성 유지.
- 운영 페이지 `https://mokku-party.vercel.app/#/ops`의 채널 목록 및 행동 퍼널에 위 세 유형을 별도 표기한다. 서버의 채널 정규화(`api/_lib.js`)와 브라우저(`index.html`)를 함께 변경하여 신규 파티 생성·초대·카드·메뉴 추천까지 같은 채널로 귀속한다.
- 유료 Meta 광고는 `utm_term={{placement}}` 같은 **게재 위치 URL 매개변수**가 있으면 브라우저에서 Reels/Feed/Stories 분류로 해석할 수 있도록 구현하였다. 이때 특정 채널로 명시된 `src` 값은 우선한다. `utm_source`만 쓰는 이전 링크는 미구분으로 취급.
- **주의:** Instagram 일반 릴스·피드 게시물 캡션에 적은 URL이 언제나 클릭 가능한 것은 아니다. 광고 목적지 링크·프로필 링크·스토리 링크 스티커처럼 실제로 클릭 가능한 경로에서 유입을 측정한다. 프로필에 동일한 하나의 링크만 놓으면 사람들이 릴스와 게시물 중 어디서 왔는지 자동 구분할 수 없다.
- 과거 기록은 소급 재분류할 수 없으며, 코드 병합만으로 실제 Vercel Production 재배포 완료나 실사용 이벤트 검증을 의미하지 않는다. 배포 후 세 링크의 방문, 파티 생성, 메뉴 추천, CSV 내보내기를 점검한다.

## 공식 서비스 주소 및 유입 측정 (2026-11-24 기준)

- **공식 주소:** https://mokku-party.vercel.app (Vercel 프로젝트 `Production`, `Valid Configuration` 화면 확인)
- **운영 기록:** https://mokku-party.vercel.app/#/ops — Vercel 환경변수 `OPS_KEY`로 접근 보호. 운영자 키의 **실제 값은 GitHub·README·이슈·스크린샷에 기록하지 않는다**.
- **서버 연결 확인:** `/api/config` 응답에서 `ai:true`, `storage:true`, `storage_kind:"upstash"` 및 카카오 키 설정 여부가 확인되었다. 이는 *설정 존재* 확인이며 실제 AI 호출·데이터 읽기/쓰기 성공 여부는 별도 기능 테스트가 필요하다.
- **카카오 개발자 콘솔:** 새 공식 웹 도메인은 추가되었으나, 확인 화면에서는 기존 임시 도메인이 '기본'으로 선택되어 있었다. 기본 도메인을 새 주소로 전환하고 카카오톡 공유 동작을 확인할 것.
- **기존 임시 배포 주소:** 개인 이름이 포함되어 있으므로 **새 광고·공유 자료에 사용하지 않는다**. 이전 링크가 계속 작동해야 할 수 있어 정리 전 영향 확인 필요.

### 유입 채널별 공식 링크

운영 페이지 `/#/ops`는 **현재 접속한 도메인**을 기준으로 채널별 링크를 자동 생성한다. 따라서 반드시 새 주소로 운영 화면을 열어 복사한다.

| 채널 | 공식 링크 |
|---|---|
| 인스타그램 | https://mokku-party.vercel.app/?src=instagram |
| 지인 공유 | https://mokku-party.vercel.app/?src=friend |
| 카카오 오픈챗 | https://mokku-party.vercel.app/?src=kakao |
| 스레드 | https://mokku-party.vercel.app/?src=threads |
| 네이버 카페 | https://mokku-party.vercel.app/?src=naver_cafe |
| 네이버 블로그 | https://mokku-party.vercel.app/?src=naver_blog |

- 채널별 **다른 URL을 사용해야** `src` 기준 유입 통계가 구분된다. 태그가 없는 직접 방문은 별도로 집계된다.
- 단순히 `?utm_source=instagram`을 추가해도 현재 구현의 `src` 채널 분류와 동일하다고 가정하지 않는다. 광고 캠페인·소재·관심사 세트별 퍼널을 보려면 추가 UTM 필드 저장/리포팅 구현을 검증해야 한다.
- 방문자는 브라우저 기반 **익명 식별자**로 집계하므로 동일인이 기기/도메인을 바꾸면 서로 다른 방문자로 잡힐 수 있다. 이름·성별·연령·실제 관심사를 이 식별자로 알 수는 없다.
- 개인정보 보호: 게스트의 음식 제한·취향, 인터뷰 연락처 등은 공유용 CSV/화면에 과도하게 노출하지 않는다.

### 운영자 접근 키 설정

1. Vercel 프로젝트 → **Settings → Environment Variables**에서 `OPS_KEY`를 긴 무작위 문자열로 등록하고 **Production**을 포함할 환경을 선택한다.
2. 환경변수 적용을 위해 Production을 **Redeploy**한다. GitHub 코드에 키 값을 커밋하지 않는다.
3. https://mokku-party.vercel.app/#/ops 에서 키를 입력해 **기록 보기**를 누르고, 채널별 통계와 CSV 다운로드를 확인한다.
4. 키 노출이 의심되면 Vercel에서 변경 후 재배포한다. 현재 실제 등록 여부와 성공 여부는 **미확인**이다.

### Meta(Instagram) 1차 고객 반응 실험 (2026-11-24~25 진행 상황)

- **광고 설정:** 트래픽(Traffic) 목적 / 랜딩 페이지 조회 중심. 한 광고 세트 내 광고 A·B 2개. 광고 세트 **평생예산 총 100,000원(두 광고 합산)**, 설정 일정 **2026-11-24~11-29**.
- **광고 A — 라이프스타일 가치:** “술 없이 즐거운 저녁” — 건강하고 프라이빗하며 합리적인 홈파티를 제안.
- **광고 B — 문제 공감:** “난 다 좋아! 그 말에 더 고민됐다면 💌” — 호스트의 메뉴 고민과 게스트가 알러지·못 먹는 음식을 말하기 조심스러운 상황에 공감. 초대 링크로 음식 취향을 모아 메뉴를 추천받는 기능을 소개.
- **소재 제작:** 광고별 본문·헤드라인·설명 문구 정리, 이미지 제작, Meta AI 이미지 후보 비교, 크롭·가독성 점검. 광고 B의 디자인은 크림·세이지·더스티 핑크 계열의 따뜻한 홈파티/다이어리 감성으로 구성.
- **광고 진척:** 광고 2개의 등록 및 Publish 절차를 진행. **마지막으로 확인한 Meta 화면에서는 광고 A·B가 `Processing`**, 광고 B에는 `Unpublished edits`가 표시되었고, 당시 지출액은 ₩0. 따라서 **심사 승인, `Active` 전환, 실제 게재 및 성과는 확인되지 않음**.
- **방문 유입:** 광고 목적지에 `?src=instagram`, 카카오 공유에는 `?src=kakao` 사용. 광고 매체별 성별·연령·노출 집계는 Meta 광고 관리자, 서비스 내 방문→파티 생성→초대 공유→게스트 카드→메뉴 추천 퍼널은 모꾸 운영 화면에서 별도로 확인.
- **측정 유의:** 광고별 실제 예산 배분은 같지 않을 수 있으며, 서로 다른 문구·이미지와 자동 최적화가 섞이므로 엄격한 무작위 A/B 실험으로 단정하지 않는다. 광고 ID·UTM별 개별 전환 연결은 저장 필드 및 운영 대시보드 검증 전에는 단정하지 않는다.
- **후속 작업:** 광고 B 미게시 변경 확인 → 심사/게재 상태 확인 → 실제 노출·클릭·랜딩뷰·지출액 기록 → 카카오 및 Meta 유입 퍼널 검증 → 실사용자 의견 수집과 개선·재배포.

관련 이슈: [#23 Meta 광고 A/B](https://github.com/pano1215/kook_party_table/issues/23), [#24 사용자 검증](https://github.com/pano1215/kook_party_table/issues/24), [#25 최종 산출물](https://github.com/pano1215/kook_party_table/issues/25).

## 폴더 구성
- `index.html` : 앱 화면 전체(한 파일). 화면을 고칠 때는 이 파일을 직접 고친다.
- `api/` : Vercel 서버 함수. `party`(파티), `invite`·`card`(초대·취향 카드), `track`(방문·전달 기록), `lead`(인터뷰 신청), `ops`(운영 기록), `ai`(AI 대리 호출), `config`(연결 상태), `_lib`(공통).
- `supabase.sql` : Supabase에 한 번 실행하는 표·보기 설정.
- `assets/` : 화면에 쓰는 사진·스티커 이미지.
- `hero.jpg`(선택) : 올리면 첫 화면 그림 대신 보이는 사진.

## Vercel 환경변수
| 이름 | 필수 | 설명 |
|---|---|---|
| SUPABASE_URL + SUPABASE_SERVICE_ROLE_KEY (또는 SUPABASE_SECRET_KEY) | 저장소 택1 | Supabase에 저장. 있으면 Upstash보다 먼저 쓴다. 아래 'Supabase 연결' 참고 |
| KV_REST_API_URL / KV_REST_API_TOKEN (또는 UPSTASH_REDIS_REST_URL / UPSTASH_REDIS_REST_TOKEN) | 저장소 택1 | Upstash Redis에 저장 |
| GROQ_API_KEY | 필수(실사용) | AI 메뉴 추천. 없으면 손님 취향이 반영되지 않는 견본 메뉴가 나온다 |
| OPS_KEY | 권장 | `/#/ops` 운영 화면에서 서버 기록을 볼 때 쓰는 비밀번호 |
| KAKAO_JS_KEY | 선택 | 카카오톡 공유 창을 바로 열 때 |
| GROQ_MODEL | 선택 | 맨 먼저 시도할 AI 모델 이름 |

환경변수를 바꾼 뒤에는 다시 배포해야 적용된다. 배포 주소 뒤에 `/api/config`를 붙여 열면 `{"ai":true,"storage":true}`가 보여야 한다.

## Supabase 연결
1. supabase.com 에서 프로젝트를 만든다.
2. 왼쪽 **SQL Editor** 에 이 저장소의 `supabase.sql` 내용을 붙여 넣고 **Run** 한다(표 `kv`, `lists` 와 보기 4개가 생긴다. 여러 번 실행해도 된다).
3. **Project Settings → API** 에서 Project URL 과 service_role(secret) 키를 복사해 Vercel 환경변수 `SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY` 에 넣고 다시 배포한다. service_role 키는 모든 데이터를 읽고 쓸 수 있는 키라 Vercel 환경변수에만 둔다(저장소·채팅·브라우저에 올리지 않는다).
4. `/api/config` 에서 `"storage":true,"storage_kind":"supabase"` 를 확인한다.
5. 파티가 만들어지지 않으면 `/api/health` 를 연다. 저장소에 쓰고 읽는 단계를 차례로 해 보고, 막힌 단계와 오류를 보여 준다(키 값은 나오지 않는다).

데이터 보기(Supabase **Table Editor** 또는 SQL Editor):
| 보기 | 내용 |
|---|---|
| `parties_view` | 파티 목록: 이름, 날짜, 인원, 유입 채널, 예산, 받은 카드 수, 추천 여부 |
| `guest_cards_view` | 게스트 취향 카드: 별명, 좋아하는 것, 알레르기, 비추, 맵기, 음료, 한마디 |
| `events_view` | 방문·핵심 행동 기록: 시각, 행동, 채널, 역할, 방문자, 파티 |
| `leads_view` | 인터뷰 신청: 휴대폰 번호, 동의 시각, 안내 버전 |

표에는 행 수준 보안(RLS)을 켜 두어 브라우저용 키로는 읽을 수 없다. 파티는 파티일 7일 뒤, 인터뷰 신청은 90일 뒤 기한이 지나면 읽을 때 지워진다.

## 브랜치 규칙
- `main` : 배포되는 최신 버전. Vercel이 이 브랜치를 자동 배포한다.
- `daily/YYYY-MM-DD` : 그날 작업을 마친 시점의 기록용 브랜치(예: `daily/2026-11-22`). 그날의 `main`에서 만들고 이후에는 고치지 않는다.
- GitHub 웹에서 만들기: 저장소 화면 왼쪽 위 브랜치 선택(`main`) → 칸에 `daily/2026-11-22` 입력 → "Create branch: daily/2026-11-22 from main".
- 그날 한 일은 아래 '작업 기록'에 날짜별로 한 줄씩 추가한다.

# 운영 메모

## 유입 경로·핵심 행동 기록
- 채널 링크: `/?src=instagram` · `friend`(지인) · `kakao`(카카오 오픈챗) · `threads` · `naver_cafe` · `naver_blog`. 값이 없으면 직접 방문, 모르는 값은 기타.
- 서버가 직접 기록: 파티 생성(`/api/party` POST), 카드 제출(`/api/card`, 새 카드만), 메뉴 추천(`/api/party` PUT, 추천할 때마다), 인터뷰 신청(`/api/lead`).
- 브라우저가 보냄(`/api/track`): 방문(세션당 1번), 초대 링크 전달(전달할 때마다, 2초 안 연속 클릭만 1번), 배달앱 이동, 바로 주문(준비 중) 버튼 클릭(`order_interest`, 재료·밀키트·배달).
- 파티에 딸린 행동은 호스트가 들어온 채널로 묶인다. 사람 수는 익명 방문자 ID(`x-visitor`, 브라우저별 무작위 16자리)로 중복 없이 센다.
- 보기: `/#/ops` 에서 OPS_KEY 입력 → 채널별 퍼널표, CSV 내려받기. 저장 위치는 Redis `events` 목록(최근 5만 건).

## 인터뷰 신청(개인정보)
- 수집 항목: 휴대폰 번호. 목적: 사용자 인터뷰 일정 안내와 사례 지급 연락. 보유 기간: 신청일로부터 90일(Redis 만료로 자동 삭제).
- 서버에 `lead:{id}`로 저장하며 동의 시각·안내 문구 버전(`NOTICE`)을 함께 남긴다. 신청자는 같은 기기에서 "신청 취소"로 바로 지울 수 있다(`DELETE /api/lead`).
- 안내 문구를 바꾸면 `api/lead.js`의 `NOTICE`와 앱의 `LEAD_NOTICE`를 같은 날짜로 함께 바꾼다.

## 첫 화면 사진 바꾸기
- 저장소 맨 위에 `hero.jpg`를 올리면 첫 화면 아치 안의 그림 대신 그 사진이 보인다(없으면 기본 그림). 직접 찍었거나 사용 권한이 있는 사진만 올린다.

## 초대 링크 보내기 창
- 파티를 만들면 초대 링크를 복사하고 보내기 창(카카오톡·인스타그램·링크 복사)을 띄운다. 호스트 화면의 "초대 링크 보내기"로 다시 열 수 있다.
- 카카오톡: 환경변수 `KAKAO_JS_KEY`(카카오 개발자 콘솔의 JavaScript 키, 사이트 도메인 등록 필요)가 있으면 카카오 공유 창을 연다. 없으면 휴대폰의 공유 창을 쓰고, 그것도 없으면 링크를 복사해 붙여 넣도록 안내한다.
- 인스타그램: 웹에서 메시지에 링크를 바로 넣는 방법이 없어, 링크를 복사하고 인스타그램 메시지 화면을 연다.
- 전달 방법(kakao·instagram·copy)은 `invite_shared` 기록의 `kind`로 남는다.

## AI 추천 연결 (사용자는 키를 넣지 않는다)
- Vercel 프로젝트 Settings → Environment Variables 에 `GROQ_API_KEY` 를 넣고 다시 배포하면, 모든 사용자의 메뉴 추천이 서버를 거쳐 AI로 만들어진다. 키는 브라우저로 나가지 않는다.
- 모델은 `openai/gpt-oss-120b` → `qwen/qwen3.8-27b` → `openai/gpt-oss-20b` 순서로 시도한다. 맨 앞 모델을 바꾸려면 `GROQ_MODEL` 을 넣는다.
- 키가 없으면 고정 견본 메뉴가 나온다(게스트 취향은 반영되지 않음). 실제 사용자에게 열기 전에 반드시 키를 넣는다.
- 확인: `/api/config` 에서 `"ai":true`.
